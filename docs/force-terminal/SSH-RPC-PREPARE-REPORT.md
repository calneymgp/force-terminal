# Force agent host preparation RPC: code-ready sub-slice

On 5 October 2026, the isolated `codex/force-agent-ssh-20261005` checkout gained `RemoteForceAgentContextCommand`, `RemoteForceAgentPrepareCommand`, and `RemoteForceAgentCleanupCommand`. All require the literal `force-agent-prepare-v1` protocol and a request nonce echoed in the response. An older helper with no command cannot silently fall back to generic file writing or job start. These handlers do not call `StartJob`, SSH, or a provider CLI.

The context call derives the current execution UID and CLI-context fingerprint from the helper's captured `InitialEnv` without creating directories, staging files, reading history, or returning HOME/config values. A caller can use that observation as the expected context for the later prepare request; prepare derives it again and rejects a change. The echoed nonce is a correlation value, **not** proof that the WSH route belongs to the authenticated SSH `Client`. Binding the route to that transport remains open.

Preparation checks the requested root, cwd, prompt snapshot/hash, expected UID, and expected CLI-context fingerprint on the execution host. The fingerprint uses the helper's captured `InitialEnv` values for `HOME` and `CLAUDE_CONFIG_DIR`, the same base map used by its job request converter, without returning those values or reading history. The executable is found from that captured `PATH` and `HOME` as an absolute path and is never executed. The response includes the protocol and nonce, host-derived UID/context, canonical root/checkout/cwd, executable path, verified prompt path/hash, observed `0700` parent and `0600` file modes, atomic staging method, and a random cleanup handle. The caller supplies no permission or atomicity flags.

The prompt and an atomic, synced `0600` receipt live under the host's private `~/.force-terminal/agent-prepares` area. Cleanup derives the location only from that private base and a 128-bit host-generated hex handle. It checks the private directory, receipt nonce/protocol/handle, and prompt mode/hash before removing its own prompt, receipt, and directory. Missing completed stages are idempotent. A fresh `ServerImpl` can use the persisted receipt to clean a previously prepared stage. Concurrent cleanup calls in one helper process are serialized; retries tolerate files already removed, and a generated empty directory with no receipt can be removed after partial cleanup. Any unexpected file blocks that recovery. Traversal, symlinked stages or prompts, altered receipts, and altered prompt bytes fail closed. Errors returned by the handlers use stable codes and preserve context cancellation/deadline; they do not include raw prompt, environment, or filesystem errors.

The WSH Debug receive path previously logged raw RPC bytes, including base64 prompt snapshots. It now logs packet length and request/response flags only; malformed packet logs also omit raw bytes. A focused test passes prompt/base64, environment, auth, success-response, and error-response sentinels through actual Debug receive, dispatch, and response handling and asserts no sentinel enters the log while the RPC response remains functional. There is no raw-packet logging in `SendRpcMessage`.

RED was observed for missing preparation handlers, then for the missing context command, and separately for base64 prompt leakage in the WSH Debug test. GREEN and race verification used temporary directories, a fake CLI with a spawn marker that was never created, and no SSH/provider/paid call. The three commands in `Taskfile.yml:force:generate` were run sequentially because `task` is absent; generated diffs are limited to the three RPC methods and six RPC data types.

**Open:** The current route does not authenticate or bind SSH host key, connection, checkout, user, attempt, or a remote writer lease to this preparation. A future authenticated bootstrap must bind the WSH helper to the exact SSH transport; comparing fingerprints/session hashes before and after these RPC calls or echoing a caller nonce cannot establish that binding. The captured `InitialEnv` can still be overridden by a later generic job request; Force execution must reject `HOME`/`CLAUDE_CONFIG_DIR` overrides and revalidate effective context at launch. The random handle is not a job lifecycle owner: cleanup requires an explicit call, and automatic cleanup across lost replies, app crashes, job exit, and host reboot remains unsolved. The receipt is synced inside the stage, but filesystem crash durability, multihelper cleanup races, and same-UID adversarial races are not claimed. The test proves no CLI spawn via a marker and handler code path; it does not insert a spy into the generic `StartJob` implementation. No Force SSH start is enabled, and real SSH/provider conversation acceptance remains open.
