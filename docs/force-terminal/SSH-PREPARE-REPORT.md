# SSH agent host preparation: code-ready sub-slice

On 5 October 2026, the isolated `codex/force-agent-ssh-20261005` checkout gained an **internal host-side preparation function** in `pkg/wshrpc/wshremote/forceagent_prepare.go`. It is not registered as an RPC and cannot start a job or a provider CLI.

The function resolves the configured root and cwd on the host, canonicalizes a Git worktree marker like the local reservation path, and rejects a symlink marker or cwd outside the checkout. It derives the execution UID and a SHA-256 fingerprint of the current user home, `HOME`, and `CLAUDE_CONFIG_DIR` without returning those values. Expected UID/fingerprint mismatches fail before staging. It finds an executable `claude` path without running it. The immutable prompt bytes are checked against the supplied hash, staged in a new `0700` directory as a `0600` file via a same-directory rename, read back and hashed, with a cleanup callback. No caller-provided Boolean is accepted as permission or atomicity evidence.

Focused RED was observed when the internal preparation boundary was missing. After implementation, `go test -race ./pkg/wshrpc/wshremote ./pkg/jobmanager ./pkg/jobcontroller -count=1` passed using only temporary files and a fake executable that is never called. Tests cover Unicode/spaces, symlink alias and marker, cwd outside checkout, UID/history change, bad hash, unavailable CLI, cancellation and deadline after rename, unsafe mode, readback tampering, missing staged file, rename failure, cleanup failure, and cleanup after failed verification. The final result uses modes returned by the verified readback, with no unchecked second stat.

**Limit:** This is host-local evidence only. There is no authenticated SSH route, host-key binding, connection binding, remote writer lease, remote process start, job liveness check, provider conversation observation, or RPC cleanup contract. The fingerprint reads the helper process environment; future jobs use its captured `InitialEnv` plus request additions, so that launch path must prove it does not override `HOME` or `CLAUDE_CONFIG_DIR`. A later slice must authenticate/bind this evidence to the connection, revalidate destination and executable immediately before spawn, and own prompt cleanup across remote job exits, failures, and app crashes; the current in-memory cleanup callback does not survive a crash. The requested Claude UUID remains separate from provider-validated identity. Real SSH, Claude, M5, and conversation-resume acceptance remain open and were not exercised here.
